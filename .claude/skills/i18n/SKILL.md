# Internationalisation (fr, en)

Decision: [ADR 0026](../../../docs/adr/0026-internationalisation.md). French is the source
language (the CV is French) and the fallback; English is a faithful translation.

## 1. The model: the locale lives in the URL

| URL                    | Serves                                                                             |
| ---------------------- | ---------------------------------------------------------------------------------- |
| `/`                    | **Gateway** (x-default): picks a locale before paint and replaces the URL          |
| `/fr`, `/fr/<slug>`    | French pages, never redirected                                                     |
| `/en`, `/en/<slug>`    | English pages, never redirected                                                    |
| `/fr/…404`, `/en/…404` | The nearest `404.html` of the locale's folder (Cloudflare Pages walks up the tree) |

- **One document = one locale.** The locale is read once, from the URL, when the page
  boots (`LocaleProvider` in `main.tsx` / `entry-server.tsx`); nothing re-renders a page into
  another language. Switching language loads the other locale's prerendered page.
- **Slugs are translated** (`/fr/mentions-legales`, `/en/legal-notice`), and so are the
  section anchors (`#parcours`, `#journey`). One typed table maps every page and section to
  its path in each locale (`src/config/paths.ts`): never write a path or an anchor by hand.
- **An explicit URL is always respected.** Only the gateway chooses. A French visitor who
  opens an `/en/…` link someone shared reads English, and can switch.

### Choosing the locale (gateway, `/` only)

1. The visitor's explicit choice, stored by the language switch
   (`localStorage['locale-preference']`, parsed like any storage read).
2. Otherwise the browser's languages, in order (`navigator.languages`): the first whose
   primary subtag is supported wins (`en-GB` → `en`, `fr-CA` → `fr`).
3. Otherwise French (the default and x-default).

The rule lives in one place: the gateway's inline script, generated by
`scripts/locale-gateway.ts` from the app's own constants (locales, storage key, anchors).
Its unit test runs the generated script in a `node:vm` sandbox against a case table
(`scripts/locale-choice-cases.ts`). The app itself never chooses a locale: it reads the
URL (`localeFromPathname`). The gateway keeps the query string and maps the hash; with
JavaScript off, a meta refresh sends to `/fr` and visible links offer both languages.

Never redirect on the server or client from an explicit locale URL, never infer the
locale from an IP address, never store a choice the visitor did not make.

## 2. Two kinds of text, two mechanisms

| Kind               | What                                                                                               | Where                                                                                                    | Shipped                                       |
| ------------------ | -------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- | --------------------------------------------- |
| **Interface text** | Short strings of shared components: skip link, header, theme toggle, video player, language switch | Colocated with the component, `const X_MESSAGES = { fr: {…}, en: {…} } satisfies Localized<XMessages>`   | Both locales, in the component's chunk        |
| **Content**        | Everything a feature displays (CV text, labels of feature components, legal pages, titles)         | Per-locale data modules `src/features/<f>/data/<name>.fr.ts` / `.en.ts`, assembled by `src/app/content/` | One chunk per locale, loaded before hydration |

- Interface text is a few hundred bytes: bundling both locales costs less than a request.
  Content is kilobytes: each locale ships only its own.
- **Feature components stay pure functions of their props.** Their text, labels included,
  arrives in their content props. They read `useLocale()` only to hand it to a pure
  formatter (`formatPeriod(period, locale)`). Shared components (`components/`, `hooks/`)
  read their interface text with `useLocalized()`.
- `src/app/content/site-content-{fr,en}.ts` import every feature's modules of one locale
  and export one `SiteContent` object; `SiteContent` (in `site-content.ts`) is the
  contract: a missing English field is a **compile error**, not a runtime fallback.
- Language-neutral data (ids, pictures, video ids, periods, stacks, URLs) is written once
  and imported by both locale modules, so it can never diverge between languages.

## 3. Typing rules

- `Locale` comes from `LOCALES` (`as const`); `Localized<T> = Readonly<Record<Locale, T>>`
  forces every locale at compile time. Adding a locale breaks every dictionary until it is
  translated — that is the point.
- **No string keys** (`t('nav.about')`): dictionaries are typed objects, read by property.
  A typo does not compile; unused text is found by Knip and review.
- Text with parameters is a **function** in the dictionary, typed by its parameters:
  `copied: (address: string) => \`Adresse ${address} copiée\``. Never build a sentence by
  concatenating fragments in a component: word order differs between languages.
- Plurals go through `Intl.PluralRules(INTL_LOCALES[locale])`, never `count > 1 ? … : …`
  (French treats 0 as singular, English as plural).
- Locale parsing at every boundary (URL segment, storage, `navigator.languages`) goes
  through `localeSchema` (`localeFromPathname` for the URL), never a cast.

## 4. Formatting and typography

- Always pass an explicit locale: `INTL_LOCALES[locale]` (`fr-FR`, `en-US`). Never
  `toLocaleString()` without argument: it would follow the build machine when prerendering.
- Dates in UTC (`timeZone: 'UTC'`) so the prerendered HTML and the client agree.
- French: narrow no-break space (U+202F) before `: ; ! ? %` and inside « », real apostrophe
  (’), "1er", "5e année". English: no space before punctuation, “ ” quotes, "1st", "5th year".
  Typography belongs to the content modules of each locale, not to code.
- Units follow the language: "56 Ko" / "56 KB".

## 5. HTML, accessibility

- `<html lang>` is the page's locale: set in the prerendered HTML by the prerender script,
  and at boot in development.
- **Language of parts** (WCAG 3.1.2): a passage in another language carries `lang` —
  the Korean words (`ko`), the French "Bonjour." of the homecoming in the English page
  (`fr`), an English job title inside a French sentence (`en`). Names, technologies and
  words adopted by the language do not.
- The **language switch** is a link to the same page in the other locale, written in its
  own language ("English", "Français") with `lang` and `hreflang` on the link. Its visible
  text is its accessible name (2.5.3). **No flags**: a flag is a country, not a language.
  It keeps the reader's **exact place** (`src/lib/reading-position.ts`): the reading block
  under the reading line (40 % down what the header leaves visible) is remembered by its
  rank, with its position on screen, for one navigation (`sessionStorage`). Both locales
  have the same blocks in the same order, so the other page puts the same block at the same
  spot before its first paint (an inline script of `index.html`), and again after
  hydration, in the same frame as the router's scroll (`useRestoredReadingPosition`,
  `ScrollRestoration`'s `getKey` then returns a key never saved). Without storage, the
  link falls back to the section's anchor.
- Every page has its own localized `<title>` and `<meta name="description">`.
- axe runs on every page of both locales, in both themes.

## 6. SEO

- Translated slugs, localized title and description, `lang`.
- `<link rel="alternate" hreflang="fr|en|x-default">` and `rel="canonical"` need absolute
  URLs: they arrive with the production origin (deployment, ADR 0014).
- The gateway is the only redirect; locale pages never redirect, so crawlers index both.

## 7. Performance

- The locale's content chunk is preloaded by the prerendered HTML
  (`<link rel="modulepreload">` injected from the Vite manifest), so it downloads in
  parallel with the entry chunk and hydration waits for no extra round trip.
- size-limit has one budget per locale chunk. Content added to one locale shows in its
  budget.
- The gateway is a static page of about 1 kB, with no JavaScript bundle.

## 8. Content rules

- French comes from `docs/content/cv-source.md`. English **translates**, it never adds a
  fact, a figure or a claim. A sentence that does not translate well is rewritten in both
  languages together, with William's approval.
- Same voice in both: first person, direct, no superlatives.
- The CV PDF exists in French only: the English page says so ("CV (in French)").

## 9. Tests

| Layer     | What                                                                                                                                                                                                   |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Unit      | Gateway script run in `node:vm` on the case table; paths: every page and section exists in each locale, slugs unique, round trip `alternateHref`; content parity (same ids, same list lengths)         |
| Component | Shared components in both locales (render with `LocaleProvider locale="en"`); the language switch (link, `lang`, `hreflang`, stored choice)                                                            |
| E2E       | Gateway with `locale: 'en-US'` / `'fr-FR'` and a stored choice; every page of both locales prerendered with its `lang` and `<title>`; switching keeps the section; 404 per locale; axe on both locales |

Playwright runs in `fr-FR` by default (the site's main audience); English tests opt in
with `test.use({ locale: 'en-US' })`.

## 10. Checklists

**New interface text**: add it to the component's `Localized` dictionary in both locales;
the component reads it through `useLocalized`.

**New content**: add the field to the feature type, fill `.fr.ts` from the CV, translate
in `.en.ts`, pass it through `SiteContent` and the route; update the parity test if a list
changes.

**New page**: add its slug in both locales to `PAGE_PATHS`, its route in both route trees,
its prerendered files, its title and description in both content modules, and its E2E and
axe entries.

## Anti-patterns

- A string key, a default string in code ("fallback to French"), or `as Locale`.
- A component deciding the language from `navigator` or storage: the URL decides.
- Concatenated sentences, `count > 1`, `toLocaleString()` without a locale.
- Flags, or a switch labelled "FR / EN" whose name differs from its text.
- Redirecting an explicit locale URL.
- Shipping every locale's content to every visitor.
